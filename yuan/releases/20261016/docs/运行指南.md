# 运行指南

## 1. 环境

推荐Python 3.11和独立虚拟环境。安装命令见根README。ML需要scikit-learn、XGBoost、LightGBM、CatBoost；神经网络/DFL需要PyTorch；MPC同时需要LightGBM与PyTorch。无需商业求解器、在线API、网页服务或PPT软件。

本次未替你安装或改变系统环境。`requirements.txt`是兼容范围，不是精确锁文件。本次实际测试环境见 `verification/环境.json`。不同库版本、线程和平台可能产生数值差异；需要逐位复现时应固定同一环境并保留输入哈希与模型产物。

只看已有成绩或订单时，不必重新训练：`python run.py reference --owner all`查看汇总；`python run.py replay --model turnover_dfl --sku 1 --through 28 --output runs/replay/sku1.csv`导出单商品；`python run.py serve --port 8793`打开离线网站。`replay`读取的是冻结订单，不会启动策略推理。

## 2. 导入数据（二选一）

在包根目录执行，后续命令保持同一workdir。

```bash
python run.py --workdir runs/exp01 prepare \
  --train "/实际路径/replenishment_train.xlsx" \
  --test "/实际路径/replenishment_test.xlsx"
```

每个工作簿有 `Period_1` 开始连续编号的工作表。列名为 `item_id`、`category`、`initial_inventory`、本表的 `demand_k`，以及 `x1`—`x20`。训练60期、测试28期。SKU顺序必须一致，需求和初始库存非负，数值字段无缺失。

如果已有本研究规范输入：

```bash
python run.py --workdir runs/exp01 prepare --npz "/实际路径/input.npz"
```

NPZ必须包含 `train_demand[N,60]`、`test_demand[N,28]`、`train_x[N,60,20]`、`test_x[N,28,20]`、`initial[N]`、`item_ids[N]`、`categories[N]`，不得含object类型数组。本研究正式N=6000；测试工具可用较少SKU。导入记录输入SHA256，随后检查未被修改。

## 3. 训练与评价

```bash
python run.py list
python run.py --workdir runs/exp01 train --models baseline moving_average ridge
python run.py --workdir runs/exp01 evaluate --models baseline moving_average ridge
python run.py --workdir runs/exp01 compare
```

每个方案具体命令见 `docs/models/<模型ID>.md`。必须先训练再评价，程序不会在工件不存在时偷偷读取历史成绩。

树SPO若缺少本轮基础XGBoost/LightGBM，会先训练该基础模型；这是保留最新版方案的依赖关系。四个融合方案共用14个需求专家和OOF缓存，选择其中任何一个首次训练会同时产生四个融合方案，避免重复拟合。`nn_scenario`等共用本轮的42期与60期概率网络预训练缓存。

```bash
# 全量训练耗时较长；先小样本测试，再决定是否执行
python run.py --workdir runs/exp01 train --models all --resume
python run.py --workdir runs/exp01 evaluate --models all
```

`--resume`只跳过已经完成的模型。它不是自动恢复训练到一半的优化器状态，也不是覆盖旧模型。要修改算法或参数，另用 `runs/exp02`重新prepare。输入目录不覆盖；显式evaluate可重新生成该运行的测试结果，不会更新选参文件。

## 4. 自测

```bash
python -m unittest discover -s tests -v
python -m tests.smoke
# 明确需要所有模型小样本链路检查时
python -m tests.smoke --models all
```

smoke使用固定随机种子的24SKU、60/28期合成数据，在系统临时目录训练并输出结果。终端会打印该临时路径。它只验证程序是否走通、工件能否载入、指标能否生成，不能说明真实数据上的模型优劣。

## 5. 读取逐SKU或轨迹

用Excel打开 `results/<模型>/test/sku_metrics.csv`。总体汇总看 `summary.json`，横向比较看 `comparison.csv`。完整库存轨迹可以这样读取：

```python
import numpy as np

path = 'runs/exp01/results/lightgbm/test/trajectory.npz'
with np.load(path, allow_pickle=False) as trajectory:
    sku = 0
    print(trajectory['item_ids'][sku])
    print(trajectory['demand'][sku])  # 28期需求
    print(trajectory['ending'][sku])  # 28期期末库存
    print(trajectory['orders'][sku])  # 当期末下、下一期到的订单
```

## 6. 常见问题

- `ModuleNotFoundError`：检查是否激活了装有相应库的环境；不要在源码中追加旧电脑site-packages路径。
- 找不到模型：先train，并确认train与evaluate使用同一个workdir。
- 服务水平低于95%：可能是真实样本外表现，不是据此修改测试参数的理由。
- 结果与历史有小差异：检查Python/库版本、输入哈希、随机种子以及是否完成同一候选搜索。本次重构不声称所有模型已在6000SKU全量重跑。
- `.joblib`/`.pt`安全：只载入自己生成或可信来源的工件，不能把不可信pickle模型当普通数据文件打开。
