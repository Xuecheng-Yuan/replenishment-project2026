# 六策略补货动画：全量商品与全60期最终拟合

此动画同步当前三轮滚动验证版本，保留历史需求满足率版本。新版先在训练文件内部做三轮向前验证，冻结参数后用全部60期重新拟合，最后使用独立测试文件的28期。历史版保留原始结果和原选参规则。

## 打开方式

下载仓库 ZIP 并解压，双击本目录的 `启动演示.cmd`，或用 Edge / Chrome 打开 [动画/index.html](动画/index.html)。HTML 已内嵌数据，离线演示无需 Python、Node 或网络。GitHub 文件预览不运行网页。

总控支持版本、观察范围、周期、播放/暂停、重播和调速。点击“打开六个同步窗口”，允许浏览器弹窗，即可同步查看六种策略；也可在总控直接看六面板。`启动六窗口.mjs` 和 `启动六窗口演示.ps1` 为安装了 Playwright 的 Windows 环境提供自动窗口排列。

## 展示范围

|范围|数据覆盖|用途|
|---|---|---|
|全部商品|6000种 × 28期|检验总体服务约束、比较完整结果|
|全部爆品|480种 × 28期|解释爆品群体表现|
|全部长尾品|5520种 × 28期|解释长尾品群体表现|
|10个固定代表SKU|每类5种，各28期|观察单笔到货、销售和订单|

群体统计由全量逐商品轨迹直接汇总，不由代表SKU推算。10种商品按品类内编号固定位置选取，不按策略成绩筛选。

六种策略为传统 (s,S)、经验 SAA、不分组 DRO、爆品/长尾 DRO、特征聚类 DRO、传统区间 RO。每个面板展示本期到货、需求、销量、丢失、期末库存、正库存商品数，以及四期预测、水位和订单计划。第一期订单实际执行，后三期订单为本次计划，之后会重新滚动计算。

## 训练、验证与测试

|阶段|拟合|验证或测试|
|---|---|---|
|选参第1轮|训练1–24期|训练25–36期|
|选参第2轮|训练1–36期|训练37–48期|
|选参第3轮|训练1–48期|训练49–60期|
|最终拟合|训练全部1–60期|不再用测试集选参|
|独立测试|冻结训练所得参数|`replenishment_test.xlsx` 全部28期|

三轮验证各自承接该候选在拟合历史回放得到的库存和在途，只评价随后12期；历史回放用于初始化，采用当折拟合器，与样本外验证成绩分别解读。三轮指标先合计销量、需求、库存和正库存计数，再重算比例。

测试 Period_1 重新起算，恢复原始库存且无初始在途。每期需求发生后预测后四期，只执行最近一期订单，提前期为1；缺货丢失、不积压。测试未来需求不进入当前预测。历史版沿用其归档规则，页面明确标注版本。

## 指标

- 正库存比例 P＝期末库存严格大于0的商品期数 / 全部商品期数。总体分母为6000×28；爆品分母为480×28，长尾品为5520×28。先计算单个商品的正库存状态，不能用“仓库总库存大于0”代替。
- 需求满足率 FR＝总销量 / 总需求。
- 库存需求比 J＝累计期末库存 / 累计需求，越低越好。它不等于常规“销量 / 平均库存”的库存周转率。

页面分别展示本期指标、截至本期期末的累计指标和完整28期结果。新版总体目标为95%≤P≤95.5%；历史版为FR≥95%。分类和单商品统计用于解释，不替代总体约束。达标标记由真实数据动态计算，未达标时不宣称存在满足约束的最优方法。

货架格子、人物、期内步行动作为示意，不是原始顾客到达过程。群体目标水位为逐商品水位之和，订单仍先逐商品决策后汇总。最后一期订单于第29期到货，未计入前28期在手库存。

在仓库根目录运行以下命令，可从完整保存轨迹重新生成并核验页面。依赖使用项目现有的 NumPy、pandas，无需重训：

```bash
python scripts/build_animation.py
python scripts/verify_animation.py
```

可选浏览器核验需安装 Node 和 Playwright（`npm install playwright`），运行 `node scripts/verify_animation_browser.mjs`。检查六种策略、所有范围、两版切换、六个弹窗同步、播放控制、手机宽度与公式互动。浏览器截图写入 `output/playwright/animation/`。

`SHA256SUMS` 覆盖本目录交付文件；本机运行记录 `动画/最近启动状态.json` 不提交。
